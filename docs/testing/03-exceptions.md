# Крок 5.3 — Демонстрація винятків

> 03.11.2026. macOS 27.2, світла тема (D-39). Знімки — `docs/report/figures/exceptions/E-x.png`.
> Знімав Claude через Accessibility, без натискань клавіш. Файли — копії `samples/broken-*.txt`.
> Перед E-1…E-3 і E-7 у програмі відкрито `vacancies.txt` (28 вакансій), щоб було видно, що каталог не змінився.

## 1. Як влаштовано

- **Один тип винятків** — `enum VacancyError: Error` (`Model/VacancyError.swift`, 15 випадків). Кожен випадок несе
  потрібні дані: номер рядка, назву поля, хибне значення. Аналог у C++ — клас винятку з полями й `throw`.
- **Хто кидає (`throw`):**
  - `VacancyFileReader` під час читання оператором `>>` — помилки формату рядка;
  - `Vacancy.validate()` — правила даних, однакові для форми й файлу. Для файлу читач додає до помилки номер рядка
    (`invalidData`);
  - `CatalogOperation.checkNotEmpty` — на початку кожної функції 1–6.
- **Хто ловить (`do-catch`):** `CatalogViewModel` (`open`, `saveDraft`, `run`) і показує алерт.
  Заголовок алерта — `alertTitle`, текст — `alertMessage`: опис помилки й порада, що робити, а для помилок відкриття ще
  «Каталог не змінено.»
- **Чому каталог не змінюється:** `VacancyCatalog.load(from:)` читає всі вакансії в тимчасовий масив і замінює
  `vacancies` лише тоді, коли файл прочитано до кінця без помилок (D-23).
